# 《明日方舟：终末地》工业界面风格调研

> 目的：把《终末地》那套被称作「工业界面」的视觉语言拆到**可以照着画的粒度**，并给出落到 MirrorpondHUD（镜潭一览）的建议。
> 边界：只谈**静态视觉语言**（色、几何、排版、版式、动效节奏）。材质（毛玻璃 / 桌面取样 / 取图后端）不在此列 ——
> 按 [`theme-system.md`](../theme-system.md) 的划界，那是「能力」而不是「外观」。
> **判据**：取舍以**美观**为第一标准，成本不进筛选器。凡「更好看但要多写代码」的，一律按更好看成文，
> 成本只在 §7 里决定先后顺序。

---

## 1. 一句话结论

**它的「工业感」不来自「深色 + 荧光 + 斜切」，而来自四条可复用的规则：**

1. **中性基底**：13 级纯灰阶承担全部表面与文字，不带色偏；
2. **颜色有角色**：黄管「可点 / 已选中 / 进度」，橙管「提醒」，蓝管「量值」，红管「危险」，互不替代；
3. **形状有含义**：直角 = 信息，切角斜楔 = 行动 / 机械 / 权限，圆环 = 人 / 技能 / 仪表，胶囊 = 对话 / 筛选 / 资源；
4. **层级靠字号字重与线，不靠装饰**：标题与正文几乎同一种墨色，差别在大小、粗细和一条 3px 的竖条。

三条与直觉相反、且直接影响做法的事实（证据见 §3）：

| 直觉 | 实际 |
|---|---|
| 主行动是「黄色切角按钮」 | **白色胶囊 + 圆形图标章**。黄色留给选中与进度 |
| 全直角才是终末地 | 官网**直角为主**（按钮 4px 微圆角）；游戏界面**按语义混用**切角、圆弧、胶囊 |
| 数字一律等宽 | 官网 CSS **没有** `tabular-nums`；要的是「数字不抖动」这个**效果**，靠独立字体角色实现 |

## 3. 设计语言解剖

### 3.1 前提：先选「载体」，再选「家族」

规范把页面分成四种载体（官网、云游戏页、游戏界面、宣传物料），并明确：**官网和游戏界面不是同一套规则**。

| 维度 | 官网 | 游戏界面 |
|---|---|---|
| 任务 | 展示、吸引 | 操作、查找、比较 |
| 密度 | 低 | 高 |
| 基底 | 白为主 | 亮暗并存，按界面功能选 |
| 强调色 | **一种黄** | 黄 + 橙、蓝、青、红、绿、紫，各有分工 |
| 形状 | 直角为主 | 切角、斜楔、圆弧、胶囊按语义混用 |
| 选中 | 填充反转、边条 | 另有角括号、白色反转、选中环 |
| 输入 | 鼠标、触屏 | 另有键盘与手柄，带键位提示 |

共同底层逻辑：**中性基底、颜色有角色、主角偏心、信息靠边、形状有含义。**

> 把「官网的直角」和「游戏界面的切角」混在一起谈，就会得出「全直角 + 斜切」这种自相矛盾的风格。

### 3.2 色彩：中性灰阶 + 一个信号色 + 一组角色色

**中性阶（13 级，纯灰，R = G = B，官网实测）**：

| 阶 | 值 | 用途 |
|---|---|---|
| neutral-0 | `#FFFFFF` | 亮色画布 |
| neutral-50 | `#FAFAFA` | 亮色页面底 |
| neutral-100 | `#F2F2F2` | 凹陷区 |
| neutral-200 | `#E6E6E6` | 分隔、轨道 |
| neutral-300 | `#D9D9D9` | 控件底、暗色页正文灰 |
| neutral-400 | `#B3B3B3` | 三级文字（仅大字 / 装饰） |
| neutral-500 | `#8A8A8A` | 暗色页次级 |
| neutral-600 | `#626262` | **次级文字正解**（白底 6.10:1） |
| neutral-700 | `#484848` | 深色控件、横带 |
| neutral-800 | `#383838` | 深色控件主档 |
| neutral-850 | `#282828` | 暗色 raised |
| neutral-900 | `#191919` | 暗色画布 |
| neutral-1000 | `#141414` | 暗色最深凹陷 |

纯黑只用于暗色主题最深的凹陷区。官网次级文字实际用 `#808080–#999999`（白底不到 4:1），规范改成 neutral-600 —— 这条是规范的「推断」，但方向正确，本文采纳。

**信号黄**：`signal #FFFA00`、`signal-deep #EEEA00`、**`signal-ink #6B5D00`**。

实测（本文脚本）：

| 组合 | 对比度 | 结论 |
|---|---|---|
| `#FFFA00` on `#141414` | **16.60:1** | 暗底上直接当文字 |
| `#141414` on `#FFFA00` | **16.60:1** | 黄作**填充**，字是墨色 |
| `#FFFA00` on `#FAFAFA` | **1.06:1** | 等于看不见 |
| `#FFFA00` on `#F2F2F2` | 1.01:1 | 更糟 |
| `#6B5D00` on `#FAFAFA` | 6.31:1 | 亮色表面的「黄字」正解 |
| `#6B5D00` on `#F2F2F2` | 5.88:1 | 同上 |

> 黄色只有两种合法形态：**实心底 + 墨字**，或**墨底上的亮色字**。亮色页面要「黄字」，必须换 `signal-ink`。
> 规范把这套切好的令牌叫 `accent-ink`（亮色取 signal-ink，暗色取 signal）。

**游戏内更暖的黄**：`#FCEA00`（本文实测 on `#141414` = 14.83:1）。规范的做法是把 `--ef-action` 覆盖成它，其余规则不变。

**角色色（社区取色，`社区` 级）**：

| 想表达 | 用 | 参考值 |
|---|---|---|
| 可点、已选中、有新内容 | 黄 | `#FFFA00` |
| 完成了多少（进度） | **黄填充 + 灰轨** | — |
| 提醒、还剩多久、折扣 | 橙 | `#FC6C00` |
| 涨了多少（增益） | 荧光黄绿 | `#BCE41D` |
| 数量、图表 | 蓝 | `#2A84B4` |
| 地区 / 机构 | 青 | `#06A2A2` |
| 危险、超支 | 红 | `#F62A2A` |
| 确认、充裕 | 绿 | `#00D872` |
| 有多稀有 | 蓝 → 紫 → 金 → 橙 | 底部渐变 / 底边条 |

两条易混：**进度归黄、量值归蓝**；**橙是「注意」，红是「危险」**（倒计时充裕是绿，紧迫才红）。

纪律：大面积只用中性色；主题色可接管，**语义色不能丢**；**状态不能只靠颜色**，必须配图标或文字。

> 角色色是按「填充」取的，直接当文字大多不达标：`#F62A2A` 压纸底 3.81:1、`#2A84B4` 压纸底 3.98:1。

### 3.3 形状：四类语义、四档圆角、三档切角

| 形状 | 表达什么 | 用在哪 |
|---|---|---|
| **直角** | 信息、默认状态 | 面板、卡片、标签、表格行、页签、弹窗 |
| **切角 / 斜楔** | 行动、机械、权限、导航 | 主行动块、等级带、选区角钩、养成页斜向结构 |
| **圆、弧** | 人、技能、仪表、范围 | 头像、圆形翻页钮、进度环、刻度环、旋钮 |
| **胶囊** | 对话、筛选、资源、短状态 | 筛选器、货币条、倒计时、切换器轨道 |

三条原则：

1. **默认是直角**；面板、标签、表格都不倒角，**按钮一族例外：4px 微圆角**；
2. **不要把任何一种形状推到极致** —— 全直角呆板，全切角做作，**对比**才是味道；
3. **同一语义全站同一种形状**。

**圆角只有四档**（没有 8 / 12 / 16px 的「现代卡片圆角」）：`0` 默认、`2px` 小标签 / 播放钮、`4px` **按钮一族** / 缩略图、`6px` 卡片图、`full` 胶囊与正圆。要柔和感时**直接用胶囊或正圆**，不要中等圆角折中。

**切角（游戏界面专属）**：`--cut-sm 6px`（≤28px 高）、`--cut-md 10px`（32–48px）、`--cut-lg 16px`（≥56px）；**45°**；尺寸约为**元素高度 1/4**；**一个元素只切一个角**（右上或右下），对角各切一个 = 更强机械感，**四角全切不用**；**只给行动 / 导航 / 权限**切，正文卡片、气泡、筛选项不切；**一屏 2–3 处**，否则不再表达任何东西。

**线**：

| 用途 | 粗细 | 颜色 |
|---|---|---|
| 发丝分隔线 | 1px | `line` |
| 控件竖向分隔 | 2px | `line` |
| 黄底 / 深底分隔 | 2–3px | `signal-deep` 或白 30% |
| **强调竖条**（列表当前项左缘） | 3–4px | `signal` |
| 图标与文字之间 | 1px | 字色 30% |
| 角括号、角钩 | 2px | `ink` / `ink-tertiary` |

**竖向分隔线不通顶**（约容器 2/3 高）；**强调竖条是最常用的低成本强调** —— 3–4px 黄短线放左缘，长度约容器一半。

**不围整圈边框**：默认不描边，靠**底色差 + 一条边线 / 左缘色条**交代。整圈只在有理由处：浮层、输入框 outline 变体、本身就是「形状」的小标签 / 筛选胶囊 / 步骤节点、物品格与投放区、高对比补线。

**阴影是环境光，不是投影**：全部 `0 0 <模糊> rgba(0,0,0,α)`，**零偏移**（xs 4px/25%、sm 8px/25%、md 12px/30%、lg 24px/30%、rail 12px/10%）。

规则：阴影只用来分**浮在内容之上**的东西，**不用来做卡片层次**（卡片靠底色差与 1px 线）；**悬停不加大阴影、不上浮**；**辉光几乎不用**，不要给选中态加发光描边。

### 3.4 选中与状态：五种手法，一概不用发光

| 手法 | 说明 | 例子 |
|---|---|---|
| 填充反转 | 底色变黄，或深浅互换 | 导航激活项黄底 |
| 边条 | 左缘或底边一条实色短条 | 列表选中项左缘黄条 |
| **角括号** | 四角各一个 L 形短线 | 物品格选中 |
| 选中环 | 圆形元素外加一圈实色环 | 头像黄环 |
| 位移 | 文字 / 图标平移让位给箭头 | 页签激活 |

角括号规格：**2px** 粗、臂长 **12–14px**、**外扩约 4px**。

状态：选中（上述至少一种）；禁用（降强调但**保持可读**）；锁定（锁图标 / 准星占位，**不整体变灰**）；完成（明暗反转 + 黄区 + 描边大词）；新内容（黄色 NEW 小签）；加载（布局稳定，**不伪造数据**）；空（解释为什么空、下一步做什么）。

### 3.5 排版：两种文字，两个层次

| 角色 | 官网字体 | 开源替代 |
|---|---|---|
| `font-sans` 中文正文 | 自托管黑体（推断 HarmonyOS Sans SC） | HarmonyOS Sans SC → Noto Sans SC → 系统黑体 |
| `font-display` 巨型英文 | **Novecento Sans Wide** | Archivo（width 125）→ Montserrat |
| `font-latin` 英文标题 / 标签 / 代号 | **Gilroy** | Outfit → Urbanist |
| `font-tech` 数字 / 技术微标 | **Space Grotesk**（SIL OFL） | 同款 |
| `font-mono` 代码 / 严格等宽表格 | JetBrains Mono → 系统等宽 | 同 |

**英文分三种脾气**：宽体用于巨字，几何体用于标题与标签，技术字用于数字。中文是阅读层，英文是**结构层**。

**字阶「跨度大、中间档少」**（正文 16px）：

| 令牌 | 尺寸 | 比例 | 用途 |
|---|---|---|---|
| text-ghost | `clamp(5rem, 10.4vw, 12.5rem)` | 10.4× | 镂空巨字 |
| text-5xl | 72px | 4.5× | 代号 |
| text-4xl | 52px | 3.25× | 页面标题 |
| text-3xl | 40px | 2.5× | 色带标题 |
| text-2xl | 32px | 2× | 中文分节标题 |
| text-xl | 24px | 1.5× | 英文分节标题 |
| text-lg | 20px | 1.25× | 按钮、页签 |
| text-base | 16px | 1× | 正文（行高 **1.6**） |
| text-sm | 14px | 0.875× | 标签、导航 |
| text-xs | 12px | 0.75× | 英文小标 |
| text-micro | 10px | 0.625× | 技术微标签 |

**不要在 16px 和 32px 之间塞很多档。** 标题行高 **1**，正文 1.6。

字重：400 正文；500 按钮 / 标签；700 中文标题；300 仅 `font-latin` 大号代号；800 仅 `font-display` 巨字。
字距：幽灵巨字 `−0.04em`（背景巨字 `−0.08em`）；短标签 `0.05em`。

**数字不抖动**是效果要求，不是全局套 `tabular-nums`：官网 CSS 没有 `font-variant-numeric`；做法是**数字用独立字体角色**，只在表格列要求严格等宽；宽体巨字的数字是比例宽度，因为巨字不参与对齐。

**微文字必须是真话**：写真实的分节名、版本号、坐标；不要用乱码与编造读数充数。

### 3.6 系统外壳

| 部件 | 做法 |
|---|---|
| 面包屑 | `// 模块 / 子页`，左上角 |
| 分组标题 | 左短竖条（黄或主题色）+ 标签；或深色横带 |
| 通知 | 橙色菱形 / 方块角标 |
| 未读 | 黄色角形横幅 |
| 倒计时 | 胶囊，绿充裕、红紧迫 |
| 货币与资源 | 顶部胶囊，圆形图标 + **等宽数字** |
| 键位提示 | 白色小方块键帽，**独立成层** |
| 系统页脚 | 延迟、版本、UID，角落小字 |

### 3.7 动效：短、直、不过冲

时长令牌：`instant 50` / `fast 200` / `base 300` / `slow 400` / `slower 600`（ms）。缓动四档，**全部不过冲**；规范明确反对「弹」的曲线，也不引入更「顺」的自定义减速曲线。

入场一律 `ease-out`，位置与擦入 300ms；**状态记号**（勾、圆点、括号）进出 200ms，不硬切。

> 动效的完整拆解（编排与错开、标志性动画、开屏三段式、减少动态效果、宜忌）见 [`endfield-motion.md`](endfield-motion.md)。

### 3.8 六类界面家族

| 家族 | 主角 | 结构要点 | 避免 |
|---|---|---|---|
| **A 运行界面与系统枢纽** | 场景本身 | 中心留空，四角停靠；主菜单是径向枢纽（中央圆形地图 + 沿弧磁贴 + 顶部胶囊货币 + 底部黄色楔形行动区）；圆形技能钮带冷却弧 | 全做成同尺寸黑黄磁贴；装饰线遮挡场景 |
| **B 地图与区域** | 区域 / 路线 | 全幅地形 + 边缘区域导航 + 跟随选区的详情卡；等高线、范围圆、节点、路径；未探索区斜纹 | 普通仪表盘网格；所有区域同时高亮 |
| **C 角色与装备** | 人 / 装备 / 等级 | 主体最大，属性与导航停侧边；养成页可用**巨型黄色斜楔或扇面**做整页结构；浅灰摄影棚 + 透视网格 + 站位刻度圈 + 幽灵大数字 | 每项属性一张独立卡 |
| **D 仓库、商城与矩阵** | 矩阵，焦点是当前物品 | 密集网格 + 筛选 + 局部详情；白卡、稀有度底部渐变（蓝→紫→金→橙），最高档叠细斜纹；选中角括号或白描边 | 为风格破坏扫描效率 |
| **E 技能树与流程** | 路径 / 节点 / 门槛 | 连线支配版式；浅纸底 + 黄色图标板节点 + 黄色直角折线；阶段用幽灵大数字；完成打黑色圆勾 | 把流程塞进卡片列表 |
| **F 数据简报与监控** | 主结论或异常项 | 浅色画布 + 深色数据行带 + 行内小面积图；列头灰色胶囊带；数字语义固定（蓝产出 / 黄进度 / 红超支） | 套通用后台模板；彩虹图例 |
| **G 通讯与信息工具** | 当前人物 / 文档标题 | 阅读列 + 列表索引；对话暗底、气泡圆角、未读黄角幅；任务优先级图标语义；百科极简浅底 + 蓝图网格 + 幽灵编号 | 牺牲行长与对比度 |

**选家族问四件事**：在行动、查找、比较、阅读还是被吸引？主角是空间、人物、矩阵、流程、对话还是数据？持续操作还是一次性阅读？主题来自功能、角色、地区还是活动？

### 3.9 装饰元素：每样都有「只用在哪」

| 元素 | 规则 | 用在哪 |
|---|---|---|
| 切角 / 斜楔 | 45°；6/10/16 ≈ 高度 1/4；一个角；斜楔 −10°~−15° | 主行动区、等级带、选中页签、养成页巨型斜楔 |
| 角括号 | 2px、12–14px、外扩 4px | 选中物品格、强调标题（左上 ┏ / 右下 ┛） |
| 方括号 | 只给名称，分节标题不加 | 宣告、代号 |
| 斜纹 | 45°，只作语义填充 | 危险 / 施工 / 未探索 / 稀有度最高档 |
| 网格与等高线 | 是坐标系不是纹理 | 摄影棚背景、蓝图、技能树底 |
| 鬼影字 | 10.4×、镂空、tracking −0.04em | 分区、阶段、背景大数字 |
| 章节标题 | 中文标题 + 左短竖条；**竖条用 ink 不用黄** | 分节 |
| HUD 叠层 | 扫描线 / 角刻度 / 准星，极低对比 | 只作氛围，不盖信息 |

## 4. 四处流行说法，逐条校正

| 说法 | 证据 | 结论 |
|---|---|---|
| 「终末地风格 = 全直角」 | 官网 `border-radius: 0` 是主流，但按钮 4px、标签 2px、头像正圆、导航胶囊；游戏界面切角 / 斜楔 / 圆弧 / 胶囊**按语义混用** | **半假。** 直角是「信息的默认形状」 |
| 「主行动是黄色切角按钮」 | 游戏界面主行动 = **白色胶囊 + 圆形图标章**；次行动 = 深色胶囊 | **假。** 规范专门点出「和很多人的印象相反」 |
| 「特征是窄体压缩大写拉丁」 | 实际是 **Novecento Sans Wide**（宽体）；压缩字另有 Oswald | **假。** 宽体用于巨字 |
| 「数字全部等宽 / `tabular-nums`」 | 官网 CSS 无 `font-variant-numeric`；规范要求的是「数字不抖动」的效果 | **半假。** 表格列要等宽，巨字允许比例宽度 |

> **自我修正**：本文早先版本依据二手复刻主题，把「全直角」「一律等宽」当成特征。按设计规范，这两条初判都过窄。

另外两个来源不在终末地的说法：**青色 `#14d0d0` 不是官网强调色**（某复刻主题的「武陵青」自创）；**绿色不是「仅用于在线」**（`#00D872` 是「确认 / 充裕」，官网上还是校准色条的一格）。

## 5. 游戏内「集成工业」（AIC）界面

按 §3.8，AIC **不是新家族**：它同时借用 **E（技能树与流程）** 的「连线支配版式」与 **F（数据简报）** 的「数字语义 + 数据行带」。

> 外观与动效的**实现规格**（画布底纹、节点与连线、通电与框选动效、数据结构与性能预算）见 [`endfield-aic.md`](endfield-aic.md)。

### 5.1 屏幕分区

| 位置 | 组件 | 行为 | 等级 |
|---|---|---|---|
| 顶部 | 探索 / AIC 模式切换（Tab） | 全屏工厂界面 | 一手 |
| 底部 | 设施列表 | 顶视图内快速建造 | 一手 |
| 右侧 | 蓝图面板、模拟教学 Tab | 面板切换 | 社区 |
| 右下 | AIC 操作菜单（建造 / 收纳 / 拆除） | 进入操作模式 | 社区 |
| 右上 | 基础 AIC 计划、蓝图分享 | — | 社区 |
| 场景内 | 点击设施 → 设施详情面板 | WASD 平移 + 滚轮缩放 | 一手 |

### 5.2 编辑动作是「模式」，不是「每条目上的按钮」

顶视图是独立相机模式；拆除模式进入后才能长按框选、整体拆除；收纳 / 蓝图同样是「进入 → 框选 → 执行 → 退出」，框选区域填充变蓝。

抽象成一句：**状态交给模式，条目只留信息。**

### 5.3 状态反馈：让端点发光，而不是画一条线

连接正确时设施**发白光**，是玩家判断连接成功的唯一可靠判据（社区）；官方公告明确「改进运输带与管道的视觉反馈以表明连接是否正确」（一手）。

对应 §3.4：状态不靠发光描边，但**靠明度**；且必须落在**它所属的对象**上。

### 5.4 数值习惯

产能按**每分钟、一位小数**（`30.0/min`）；电力用 `kW` / `W`，区域初始容量 200；资源量成对出现「用量 / 上限」。

### 5.5 官方自己的可用性补丁史

多个版本都在补：引导提示、连接视觉反馈、移动端顶视图、管道批量操作、蓝图超限显示数量、`[Continue Placing]`。

> **这套界面好看，但初版不好懂。** 对 HUD 的启示：**借风格，不借交互复杂度。**

### 5.6 未确认

网格底纹、选中框形态、流向箭头、分段进度、缩放条 / 小地图、数值是否等宽。NGA 帖标题可确认但正文 403，**不引用其论点**。

### 6.4 `industrial` 段怎么配才像终末地

`.mptheme` 现在支持 `industrial` 与 `motion` 两段（[`ThemeFile.cs`](../../src/Core/ThemeFile.cs)），推荐值：

| 键 | 推荐 | 理由 |
|---|---|---|
| `industrial.monoReadouts` | `true` | 读数不抖动，是「仪表感」的第一来源 |
| `industrial.decoration` | 墨版 `Grid`；纸版 `Contour` | 网格 = 蓝图底；等高线 = 官网签名 |
| `industrial.decorationDensity` | `0.35` | 规范网格线 8% 白；超过 0.5 就抢读数 |
| `industrial.contourLevels` | `12` | 代码默认值；够密，又不抢读数 |
| `industrial.contourRelief` | `1.0` | 默认起伏 |
| `motion.profile` | `Industrial` | 补位 120ms / 显隐 110ms / 偏移 2px，比 `Current` 更「切」 |
| `motion.effect` | `None` | 常驻叠层不做循环；用户想要「呼吸」再自己开 |

> `MotionProfile` 的三个档位正好对应三种气质：`Current`（缓、8px 位移）偏产品，`Cut`（线性、无位移）偏硬切，`Industrial`（120ms、2px）**就是为工业界面留的那一档**。

### 6.7 WPF 的等价做法

| 规范做法 | WPF 等价物 | 坑 |
|---|---|---|
| `clip-path` 切角 | `Path` + `StreamGeometry` 多边形做底，文字压在未裁层 | 直接 `Clip` 会把焦点框 / 描边一起裁掉 —— 规范的做法是「**外层留焦点环，内层画切角**」 |
| 切角带描边 | 两层 Path：外层描边色、内层缩进 1px、同一多边形 | 斜边上本来没有线，要叠层补 |
| 角括号 | 4 条细 `Rectangle` / `Line`（2px × 12–14px），外扩 4px | 不要用 `Border` 的四角 `CornerRadius` 冒充 |
| 左缘色条 | 独立 `Border`（宽 3–4px）叠在内容左侧 | **别用不等宽 `BorderThickness`** —— `Border` 四角会斜接出小斜边 |
| 零偏移阴影 | `DropShadowEffect { ShadowDepth = 0, BlurRadius = 26, Opacity = 0.28 }` | `ShadowDepth = 0` 时 `Direction` 无意义 |
| 悬停 | 只换底色 / 字色 | **不加大阴影、不上浮** |

现实约束：WPF 的任意多边形 + 抗锯齿不如 `clip-path`，所以切角**只用在 2–3 个高价值控件**（主行动块、选中标签、角标）—— 这正合规范的「一屏两三种」。

| 位置 | 元素 | 依据 |
|---|---|---|
| 左上 | `// 03 / 硬件` 面包屑 + 编号 | §3.6、§3.5 微文字 |
| 右上 | `ONLINE` 等宽大写小标 | §3.6、§3.5 英文结构层 |
| 分区 | **1px 发丝线**，不通顶 | §3.3 线宽 |

### 6.9 动效

- 用 `MotionProfile = Industrial`（补位 120ms / 显隐 110ms / 偏移 2px），**不要**用 `Current` 的 160–180ms + 8px；
- 状态记号（勾、点、括号）进出 200ms，位置变化 300ms，`ease-out`，**不用过冲**；
- `CardStatus` 的盲文转圈改成分段方块脉冲（`▮▮▯`），既合节奏也少一格字宽抖动；
- `LoopEffect` 保持 `None`；毛玻璃开启时动效全关（模糊重绘远贵于动画）。

### 6.10 验收六问（规范原表，改成 HUD 版）

1. 五秒内能看出主要任务和当前选中项吗？
2. 把信号黄全部去掉，结构与交互还成立吗？
3. 形状在表达语义，还是所有卡片共用一个外形？
4. 能指出这张卡属于哪个家族吗？
5. 颜色遵守角色分工了吗 —— 有没有把红当装饰、把橙当错误、把黄铺成大底？
6. 长文案、加载中、空数据、出错四种状态都可用吗？

### 6.11 版权与素材

- **不分发** Novecento Sans Wide、Gilroy（商业字体）；`Archivo` / `Outfit` / `Space Grotesk` 是 OFL，可自托管到 `assets/`，与现有 Lucide 字体同一条路，不破坏「零第三方依赖」；
- **不要**把游戏内 UI 截图、字标、角色立绘打进仓库；
- 设计语言（灰阶、形状语义、线宽、角括号）属风格借鉴，可以；把「终末地」字标当装饰不行。
