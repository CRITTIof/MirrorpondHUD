# 《明日方舟：终末地》工业界面风格调研

> 目的：把《终末地》那套被称作「工业界面」的视觉语言拆到**可以抄的粒度**，并给出落到 MirrorpondHUD（镜潭一览）的具体建议。
> 边界：本文只谈**静态视觉语言**（色、几何、排版、版式、动效节奏）。材质（毛玻璃 / 桌面取样 / 取图后端）不在此列 ——
> 按 [`theme-system.md`](../theme-system.md) 的划界，那是「能力」而不是「外观」，同一套配色在四种材质下都应成立。

## 1. 结论先行

| 特征 | 证据与出处 | 能否迁移到 HUD |
|---|---|---|
| **墨 / 纸 / 单信号色** 三层色，信号色只标「需要被看见的那一处」 | A 层 CSS 统计与两份独立设计归纳指向同一结论；实测对比度见 §3.1 | ✅ 迁移，但要把「一处」落实为「一屏一处」 |
| **直角矩形 + 单侧粗色条 + 1px 细框 + 角标三角** | [PRTS Design · 装饰语言](https://mooncellwiki.github.io/prts-design/foundations/decoration) 明确写「没有切角、斜切、斜带」 | ✅ 最值得抄的一条，且 WPF 可低成本实现 |
| **宽体大写拉丁只做装饰，中文永远是主角** | 官网字体为 Novecento Sans Wide（宽体）；同族字体链见 §3.3 | ✅ 迁移「只做装饰」的用法，不迁移具体字体 |
| **数字分场景**：HUD 大字（比例宽度、粗体）vs 表格列（tabular-nums） | PRTS Design 记录 Bender 数字是比例宽度、子集不带 `tnum` | ✅ 比「全部等宽」更准确，也更省事 |
| **状态靠明度反转而非彩色**（黑白反转 = 选中 / 激活） | PRTS Design `.ak-inverse`，出处是游戏内 `btn_on` / `btn_off`；游戏内连接成功＝设施发白光 | ✅ HUD 里就是「实心底 + 墨色字」 |
| **状态落在「它所属的对象」上**，不靠连线颜色 | 官方公告承认连接反馈不清、专程改过运输带 / 管道视觉 | ✅ 告警标在出问题的那个读数上，而不是顶部弹一句 |
| 45° 斜纹、半调网点、扫描线、等高线 | 官网实现为 `clip-path` 揭示| ⚠️ 少量点缀可以，成片铺就是「伪装工业」 |

一句话：**它的「工业感」来自工程制图式的排版纪律（编号、刻度、细线、单侧色条），而不是「深色 + 荧光 + 斜切」。**
把装饰当成风格去抄，只会得到一张「假工牌」。

第二句同样重要：**这套界面好看，但不好懂。** 官方连续多个版本在补引导与状态反馈（§5.5），
攻略站干脆教人「去模拟教学练手」。所以借它的时候，**借信息结构，别借交互复杂度**。

## 3. 风格解剖

先交代三层证据的**不同性质**，本文的结论只落在三者交叉能撑住的部分：

| 层 | 说明 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| A. 终末地官网样式统计 | 他人抓取官网 CSS 的统计结果，本文未复核 | 字体族名、圆角是否真的存在、有无 `tabular-nums` | 取值分布的具体数字 |
| B. 同族《明日方舟》体系设计文档 | [PRTS Design](https://mooncellwiki.github.io/prts-design/)，与终末地同属鹰角、共用视觉母语 | 排版纪律、装饰语汇、数字分场景这类**设计规则** | 终末地是否逐条照搬 |
| C. 游戏内 AIC 操作结构 | 社区 Wiki（一手）+ 官方公告（一手） | 信息架构、操作模式、状态反馈方式 | 具体像素与配色 |

**B 不是终末地本身。** 下文凡是引用 B 的规则，都是「同一设计母语下的规则」，不是「终末地的官方规范」。

### 3.1 三层色：墨、纸、信号

两个独立来源对同一套色的取值略有出入，区间如下（精确值待以官网 CSS 复核）：

| 角色 | 取值区间 | 用法 | 备注 |
|---|---|---|---|
| 墨（底） | `#101110` – `#191919` | 大面积背景 | 不用纯黑 `#000`，留一点绿倾向，避免「死黑」 |
| 纸（底） | `#E8E8E2` – `#F2F2F0` | 亮色模式背景 / 面板 | 不用纯白 `#fff`：带暖灰才像纸，不像屏幕 |
| 信号 | `#FFF500` – `#FFFA00` | 按钮、焦点、选中、需要被看见的那一处 | **面积越小越有效**；压纸底几乎不可见（见下表） |
| 校准色条 | `#00FFA2` / `#FF1AAC` / `#FFFA00` | 并排小色块，做「校准 / 仪表」装饰 | 绿色是装饰语义，**不是**「在线 / 已验证」专用 |

实测（WCAG 2.x 相对亮度，本文脚本计算）：

| 组合 | 对比度 | 判定 |
|---|---|---|
| `#FFFA00` on `#101110` | **17.06:1** | 远超 AA，信号黄在墨底上极其响亮 |
| `#FFFA00` on `#191919` | 15.85:1 | 同上 |
| `#FFF500` on `#E8E8E2` | **1.07:1** | 等于抹除：黄色文字压在纸底上不可读 |
| `#FFF500` on `#F2F2EC` | 1.01:1 | 更糟 |
| `#6B5D00` on `#E8E8E2` | 5.35:1 | 亮色下「下沉」后的可用金 |
| `#E8E8E2` on `#101110` | 15.38:1 | 纸白字在墨底上 |
| `#898D89` on `#101110` | 5.62:1 | 次要文字的下限参考 |

结论：**信号黄只能用「实心底 + 墨色字」或「墨底上的亮色字」两种形态，永远不能当纸底上的文字。**
亮色模式下必须换同色相的深档（`#6B5D00`），这不是审美选择，是纸的属性。

### 3.2 几何签名：直角矩形 + 单侧色条 + 1px 细框

同族体系的设计文档把签名讲得很清楚（B 层证据），且**先说了不做什么**：

> 「没有切角、斜切、斜带 —— 层级与状态靠色条、黑白反转、角标三角表达。」

可叠加的装饰件清单（全部是纯 CSS 类，可叠在任何盒子上）：

| 装饰 | 语义 | 出处 |
|---|---|---|
| 单侧 4px 粗色条 + 1px 细框 | 标题 / 消息 / 面板头的强调 | 系统内最常用 |
| `border: 1px` 细框 | 分区与「图纸感」 | 同上 |
| 45° 斜纹 | **危险 / 施工 / 禁用**，不作背景纹理 | 游戏 `btn_done`、`image_btn_ap_confirm` |
| 角标三角 | 选中 / 状态角标 | 官网右上三角、游戏 `selected_decor` |
| 半调网点 | 标题条渐隐 | `bkg_openserver` |
| 网格 / 点阵 / 扫描线 | 终端底纹 | PRTS 终端 |
| 菱形 | 源石母题（列表符、加载涟漪、时间线节点） | 独立小图形，**不是盒子的斜边** |

一个非常实用的实现细节（直接可搬到 WPF）：

> CSS 里「不等宽边框」会在四角 **斜接（miter）** 出一道小斜边，而系统里不允许出现斜边。
> 做法是把色条和细框都交给 `border-image`，让直角拼接。

WPF 同理但更简单：**别用不等宽的 `BorderThickness`（`new Thickness(4,1,1,1)`），`Border` 在转角同样会斜接。**
用两层 `Border` 叠：外层 1px 四边细框，内层左侧 4px 色条 —— 转角是干净的直角，也省掉 `border-image` 那样的技巧。

### 3.3 排版：宽体大写拉丁只做装饰，中文当主角

**字体链**（B 层同族文档；其中注明 Novecento / Bender 取自鹰角官网静态资源 `web.hycdn.cn`）：

| 角色 | 字体 | 用途 |
|---|---|---|
| 正文（中文） | 思源黑体 / Noto Sans SC，回退微软雅黑 | 行高 **1.7** |
| 展示字（拉丁大写） | **Novecento Sans Wide** 500–800 | 标题旁的英文、编号、水印：**Latin as ornament** |
| HUD 标签 / 数值 | Bender 400 / 700 | 粗体、大字号、独立出现时才成立 |
| 压缩字 | Oswald | 窄栏、长标签 |
| 等宽 | 系统等宽（Consolas / SF Mono…） | 只用于代码、编辑框、键帽 |

> 终末地官网自身的字体族名以 **Novecento Sans Wide + Gilroy + Space Grotesk** 为主（A 层转述），
> 与上表方向一致但**不完全相同** —— 上表是方舟侧的落地取值，别当成终末地的逐字规范。

注意两个反直觉点：

1. **展示字是「宽体」，不是窄体压缩。** 第三方归纳里的 `condensed` 说法不成立；A 层 CSS 统计里也没有 `condensed` 声明。
2. **数字不是「一律等宽」。** Bender 的数字是比例宽度、子集不带 `tnum`，强制 `tabular-nums` 无效。体系内的规则是分场景：
   - HUD 大字读数（属性值、统计值、等级、倒计时、关卡码）→ Bender 粗体，允许比例宽度；
   - **表格 / 列表数字列 → 正文字体 + `tabular-nums`**（思源的数字本身等宽，列天然对齐）。

**字号阶梯**（B 层同族文档记录的网页字阶，px）：11 / 12 / 14 / 16 / 17 / 18 / 20 / 24 / 32 / 40 / 56。
**字距**：大写标签 `0.08em`，overline 小标签 `0.14em`，展示标题 `-0.02em`。

**双语标题的纪律**：「一页一两处，不成排」。英文是装饰层（大写、展示字、灰色、跟在旁边或上方），**中文标题永远是主角**；
区块标题、面板标题、卡片眉题只写中文 —— 同一条信息中英各写一遍，中文读者看两遍，外文读者照样不懂中文那半。

**低分屏**：中文小字不小于 12px（9–11px 中文在 1× 屏上换哪款字都糊）。

> 对本项目的意义：这一整套都在说「**排版是装饰，不是信息**」。HUD 卡片上真正需要英文的地方只有状态与编号，
> 那正好是 `CardHeader.Badge` 那一格。

### 3.4 版式骨架：边轨 + 舞台 + 元数据基线

以下骨架来自第三方对官网的实现归纳（A 层，未逐条复核），方向可信、数字仅作参考：

- 外层是 **CSS Grid**，不是一堆绝对定位：`grid-template-columns: 4.5rem 1fr` 的竖直轨道（rail）+ 顶栏 + 舞台；
- 绝对定位只允许出现在「有边界的舞台」内部做美术调度；
- 标题块与图片**刻意叠压**，元数据落在基线附近；
- 装饰性网格：`1px` 线、`4rem` 间距、`8%` 白色 —— 网格是「坐标系」，不是「纹理」。

### 3.5 状态表达：明度反转优先于彩色

游戏内 `btn_on` / `btn_off` 的主动作是**黑白反转**，不是换彩色。
这解释了一个常见困惑：为什么这套 UI 状态对比那么强，颜色却那么少 —— 因为它把「对比」这一维单独拿去做状态，
把「色相」这一维留给信号色。

### 3.6 动效：一次性、有方向、可关闭

参数来自对官网实现的观察与同族文档（A / B 层）：

| 行为 | 参数 | 说明 |
|---|---|---|
| 遮罩揭示 | `clip-path: inset(0 100% 0 0)` → `inset(0)`，`.65s cubic-bezier(.22,.8,.2,1)` | 方向性切入，不缩放、不弹跳 |
| 黄色擦除 | 入场一次性 | 只在首屏，不重复 |
| 呼吸 / 脉冲块 | 极低幅度 | 表示「系统在跑」，不是装饰 |
| 减少动效 | `prefers-reduced-motion` 下全部瞬时 | 连续性动画在该查询下停掉 |

## 4. 三处流行说法，站不住脚

这一节是本文最有用的部分：**下面三条如果照抄，会做出一个「像，但又哪里不对」的界面。**

| 流行说法 | 证据 | 结论 |
|---|---|---|
| 「终末地风格 = 全直角，`border-radius: 0`」 | 官网 CSS 中 `border-radius: 0` 出现 **0 次**；胶囊控件 `2.625rem / 2.8125rem / 3.375rem`、圆形 `50%` 8 处、小圆角 `.25rem` 大量存在（他人统计，未复核） | **假。** 直角是「矩形块」的默认，不是全局禁令；圆形控件与圆角徽标照样存在 |
| 「特征是窄体压缩大写拉丁」 | 字体文件是 **Novecento Sans Wide**（Wide），CSS 无 `condensed` 声明；同族体系另有 Oswald 负责压缩字 | **半假。** 宽体是展示字，窄体只是备选 |
| 「数字全部等宽 / `tabular-nums`」 | 官网 CSS 中 `font-variant-numeric` 出现 **0 次**；同族文档明确 Bender 数字为比例宽度、`tnum` 无效 | **假。** 等宽只用于表格列，HUD 大字是比例宽度 |

另外两处需要修正的「二手人设」：

- **青色（`#14d0d0`）不是官网强调色。** 它来自第三方复刻主题作者的「武陵青」自创配色，官网无青色强调；
- **绿色（`#00ffa2`）不是「只用于在线 / 已验证」。** 它在官网是校准色条的一格，与品红 `#ff1aac`、信号黄 `#fffa00` 并排做装饰。

> 为什么值得写下来：这三条都是「看起来很像」的错误抽象。
> 直角 + 窄体 + 等宽数字拼起来，得到的是一种**瑞士国际主义的技术风**，而不是终末地那种「纸墨 + 单一信号」的编辑风。
> 区别不在像不像，而在**信息密度与色彩预算**完全不同。

## 5. 游戏内「集成工业」（AIC）界面

官方站把 **「玩法介绍 & 集成工业知识」** 列为并列的内容板块，社区 Wiki 又用 **PRTS 记录 / 蚀刻章 / Baker 模拟器**
这类工程化栏目组织资料 —— 术语体系本身就带「档案 / 仪表 / 校准」的味道。
真正值得看的是**它怎么组织一屏操作**，而不只是它长什么样。

### 5.1 屏幕分区

| 位置 | 组件 | 行为 | 强度 |
|---|---|---|---|
| 顶部 | 探索 / AIC 模式切换（Tab） | AIC 模式即全屏工厂界面 | 一手 |
| 底部 | 设施列表 | 顶视图内快速建造 | 一手 |
| 右侧 | 蓝图面板（我的 / 系统 / 已分享）、模拟教学 Tab | 面板切换 | 二手 |
| 右下 | AIC 操作菜单（建造 / 收纳 / 拆除） | 进入操作模式 | 二手 |
| 右上 | 基础 AIC 计划入口、蓝图分享 | — | 二手 |
| 场景内 | 点击设施 → 设施详情面板 | 顶视图 WASD 平移 + 滚轮缩放 | 一手 |

### 5.2 编辑动作是「模式」，不是「每条目上的按钮」

三条独立线索指向同一个结构：

- **顶视图**是独立相机模式（WASD 平移、滚轮缩放），不是拖动滚动条；
- **拆除模式**进入后才能长按框选，一次选中多台设施与运输线整体拆除；
- **收纳 / 蓝图**同样是「进入 → 框选 → 执行 → 退出」，框选区域填充变蓝以示选中。

把这套结构抽象一句：**状态交给模式，条目只留信息。**
这是它对 HUD 最有价值的一条 —— 批量操作不要在每个条目上散落复选框。

### 5.3 状态反馈：让端点发光，而不是画一条线

- 连接正确时设施会**发白光 / 高亮为白色**，这是玩家判断连接成功的唯一可靠判据（二手，攻略站）；
- 官方在 2026-01-17 的上线前公告里明确写道：**改进了运输带与管道的视觉反馈，以明确其是否正确连接到设施**，
  同时优化了 AIC 引导提示（一手，[官方公告](https://endfield.gryphline.com/en-us/news/4499)）。

这正好印证 §3.5：**状态用明度表达，不用色相。**
也给出了一条可直接搬的设计规则：**状态必须落在「它所属的那个对象」上**，别指望用户去解读一条线的颜色。

### 5.4 数值习惯

- 产能按**每分钟、一位小数**呈现（如 `30.0/min`）；
- 电力用 `kW` / `W` 混合，区域初始容量 200；
- 资源量成对出现「用量 / 上限」，而不是只报余量。

### 5.5 官方自己的可用性补丁史（最值得读的一节）

连续多个版本都在做同一类修补：引导提示、**连接视觉反馈**、移动端顶视图的便利性、管道批量操作逻辑、
蓝图超限时显示数量、`[Continue Placing]`（1.5）。

> 这说明一件事：**这套界面很好看，但初版不好懂。**
> 攻略站甚至建议「看不懂 AIC 就去 Simulation 练手」—— 等于承认主流程教学覆盖不了操作复杂度。

对 HUD 的启示很直接：**风格可以借，交互复杂度不要借。**
一个卡片上多一个模式，用户就多一层要记的东西；常驻叠层尤其付不起这个代价。

### 5.6 仍然未确认

网格 / 蓝图底纹、选中框是虚线还是角标、连线上有无流向箭头、生产队列是否分段、AIC 内是否有缩放条与小地图、
告警列表的条目形态、数值是否等宽字体（只能确认「按分钟、一位小数」的取值习惯）。

NGA 帖《基建系统的 UI 可读性极差》标题可确认，但访客 403、正文未读到，**本文不引用其具体论点**。

> 取舍理由：这些细节一旦写错，后面的应用建议会整段作废。
> 本文的应用建议因此只采用可迁移的**信息结构**（编号、铭牌、读数、单侧色条、明度反转、模式化批量操作），
> 不抄具体界面语法。

## 6. 应用到 MirrorpondHUD

### 6.1 三条改造原则

常驻叠层的处境和宣传页相反：**它一直挡在壁纸前面，用户看它几百次。** 因此：

| 原则 | 宣传页的做法 | HUD 的做法 |
|---|---|---|
| **一个焦点色** | 信号黄标按钮 | 信号黄只标「此刻真正要看的那一处」（告警 / 录音中 / 正在传输），一屏最多一处 |
| **明度优先于色相** | 黑白反转表达选中 | 选中行用「实心前景底 + 墨色字」，不要新增第三种彩色 |
| **静止优先于动效** | 入场擦除、呼吸块 | 只保留状态变化的一次性 150–200 ms；常驻循环动画一律不做 |

### 6.2 两套主题草案（`.mptheme`）

格式与字段见 [`theme-system.md`](../theme-system.md) §3；`foreground` / `background` 必须是 7 位 `#RRGGBB`，
软色（`muted` 等）用数字 = 按前景色派生的 alpha。两套都已按下表验算过全部文字组合。

| 组合 | 对比度 |
|---|---|
| 墨版：正文 `#F5F5F0` on `#101110` | 17.30:1 |
| 墨版：强调 `#FFFA00` on `#101110` | 17.06:1 |

| 纸版：危险 `#B4231B` on `#E8E8E2` | 5.34:1 |
| 纸版：次要文字（`0.66` 派生 ≈ `#595A57`） | 5.64:1 |

两个刻意的取舍：

- **纸版的 `muted` 必须抬到 0.66。** 沿用默认的 0.45 在纸底上只有 2.93:1，0.55 也只有 3.94:1 —— 都低于 AA。
  这是浅色主题最容易漏的一处（`theme-system.md` 的风险清单里已提过「浅色底上 0.45 会偏淡」，这里是量化值）；
- **`shadow: false`**（判断）：这套视觉里看不见投影这一层 —— 分隔靠 1px 线，不靠阴影。
  代价是深色卡压浅色壁纸时边缘要靠 `backgroundOpacity 0.92` 与 1px 细框区分；
  壁纸极亮且花时，退回开阴影或开 `TextOutline` 更实际。

> 顺带发现的现存问题：默认 `Accent` `#2F6FEB` 与默认 `Danger` `#D14343` 压在默认底 `#0D1117` 上都是 **4.14:1**，
> 差一点点不到 AA 的 4.5。`CardButton` 的 Primary / Danger 语气正是「把文字染成强调色 / 危险色」，
> 所以这两色在**当文字用**时偏低（实际值还会随 `backgroundOpacity` 与壁纸浮动，这里只是纯色底上的基准值）。
> 修法不是改默认值（会改变现有观感），而是选主题时把强调色挑到 ≥4.5 的档位 —— 本文两套草案都满足。

### 6.3 令牌层的三个缺口

主题文件只能表达「颜色 / 字体 / 圆角 / 内边距 / 面板尺寸」。下面三件事**主题表达不了**，需要动代码：

**缺口 1：状态色借用强调色。**
`CardStatus.UpdateVisual()` 把 `Success` 画成 `Accent`、`Warning` 画成前景色，`Info` 用 `Muted`。
在「单信号色」主题下，这会让「成功」和「强调」变成同一个颜色 —— 语义丢失。
建议：新增 `Style.Success` / `Style.Warning`（空串 = 现有派生，保持默认观感不变），并让 `CardStatus` 优先读它们；
主题里只给墨版 `#4FBF5C`（8.06:1）、纸版 `#1F6B2E`（5.33:1）。**不要**把绿色做成大面积色块，它只配当一个点。

**缺口 2：数字列没有等宽开关。**
全仓库没有任何 `Typography.NumeralAlignment` 设置，读数刷新时小数点位置会横向抖动。
建议：给「读数类」TextBlock（指标卡数值、`CardHeader.Badge` 的计数、图表轴标签）设
`Typography.SetNumeralAlignment(tb, FontNumeralAlignment.Tabular)`，并**说明它只在字体带 `tnum` 时生效** ——
`Microsoft YaHei UI` 不保证；`Cascadia Mono` / `Consolas` 恒等宽。稳妥做法是读数本身改用 `Style.MonoFont`。

**缺口 3：`cornerRadius = 0` 做不到「全直角」。**
多处硬编码了圆角下限，主题设 0 仍然会得到 6px / 4px / 3px：

| 位置 | 现状 |
|---|---|
| `src/UiKit/CardOverlayControls.cs:185` / `:543` | `new CornerRadius(Math.Max(6, cornerRadius))` |
| `src/UiKit/CardOverlayControls.cs:1100` | `Math.Max(8, cornerRadius)` |
| `src/UiKit/CardDropOverlay.cs:75` | `Math.Max(6, cornerRadius)` |
| `src/UiKit/CliUi.cs:186` / `:221` | `Math.Max(3, corner - 3)` |
| `src/UiKit/CardDataControls.cs:98` / `:185` / `:318` | 分别 `Math.Max(2, …)` / `Math.Max(6, …)` / `Math.Max(4, …)` |
| `src/UiKit/CardStatus.cs:68` / `:72` | 进度条 `Height = 3` + `CornerRadius(1.5)` 的**半圆端头** |

建议：抽一个 `CardPalette.Corner(double radius)`（或 `Style.Square` 布尔）统一钳制，
把这些下限改成「跟随配置」，让 0 真的等于 0。`CardStatus` 的 1.5 半圆端头单独处理：直角主题下用 0，进度条就成了分段方块 —— 反而更像工业读数条。

### 6.4 控件层改法

| 组件 | 现状 | 建议 | 收益 |
|---|---|---|---|
| `CardHeader` | 标题 + 徽标 + 右侧动作 | 标题前加两位编号（`03 / 硬件`），`Badge` 用等宽大写（`ONLINE`、`2/5`） | 抄的是**信息结构**，不是字体；编号是「铭牌感」最便宜来源 |
| `CardButton` | 透明底 + 1px 描边 + 低对比文字（已经很克制） | 直角主题下保持 1px 边；主操作才用信号色边 | 现状已接近，别加实心高饱和块 |
| `CardStatus` | 图标 + 文字 + 3px 进度条 | 直角主题下进度条去圆头；`Success` / `Warning` 读独立令牌 | 语义与形状同时到位 |
| `CardChartControls` | 折线 / 柱状，颜色走令牌 | 网格线降到 `Border` 令牌（低透明 1px），柱状改**分段** | 分段柱比渐变更像仪表 |
| `CardList` | 行高亮 | 选中行用「实心底 + 墨色字」（明度反转），不做彩色描边 | 对应 `.ak-inverse` 的做法 |
| `CardIcon`（Lucide） | 线稿图标 1.15 倍率 | 维持线稿，别填实 | 与「白色线稿图标」的语汇一致 |

一张卡片的信息架构可以固定成四段（对应 `CardHeader` / 内容 / 读数 / `CardStatus`）：

```
03 / 硬件                      ONLINE
──────────────────────────────
CPU  42%   GPU  11%   内存 61%
──────────────────────────────
■ 已稳定运行 4h12m
```

- 第一行：编号 + 名称 + 右上状态（等宽大写）；
- 细线一行：分区；
- 读数：等宽数字，单位与数值同一行但小一号；
- 底部：状态点 + 一句话，颜色只在异常时出现。

### 6.5 可以借的三条交互结构

对照 §5 的实证，值得迁移的是**结构**，不是外观：

| 借什么 | 游戏里怎么做 | HUD 里怎么做 |
|---|---|---|
| **模式化批量操作** | 进入拆除模式 → 长按框选 → 整体执行 | 「整理模式」下一次框选多张卡片：统一换主题 / 统一收起；不要在每张卡上挂复选框 |
| **端点状态** | 连接成功＝两端设施发白光 | 数据源断开时，把**那一个读数**标灰并加状态点，而不是顶部弹一条全局提示 |
| **成对读数** | 「用量 / 上限」并列，产能固定 `/min` + 一位小数 | 内存 `7.4 / 16 GB`、网速 `1.2 MB/s`：单位写死、小数位固定、右对齐 |

**不要借**：全屏模式切换（HUD 没有「一个屏幕」这个概念）、缩放 / 平移相机（卡片是定高列表）、
引导式新手流程（常驻叠层不该教用户怎么用它）。

### 6.6 动效

- `CardStatus` 的盲文转圈（`⠋⠙⠹…`）在工业语境下可换成分段方块脉冲（`▮▮▯`），既更贴题也少一格字符宽度抖动；

### 6.7 版权与素材边界

- **不要把官方字体（Novecento Sans Wide / Bender）或字标打进仓库**：它们是鹰角官网静态资源，许可不明；先找原字体的许可或相似字体。
