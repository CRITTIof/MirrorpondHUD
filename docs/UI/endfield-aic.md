# 游戏内「集成工业」（AIC）界面的外观与动效：实现文档

> 定位：这不是实机测量报告——本文**拿不到客户端数值**（规范自己也明确「游戏客户端内的任何数值都不在本页范围内」）。
> 它是一份**可实现的规格**：把已确认的信息架构、品牌层实测过的几何与动效规则，落成参数、数据结构与渲染方案；
> 凡推定项都标 `推断`，凡来自社区归纳的标 `社区`，以便后续用实机截图逐条校正。
> 边界：只讲**外观与动效的实现**，不讲玩法数值与平衡。色彩/形状总则见 [`endfield.md`](endfield.md)，动效总则见 [`endfield-motion.md`](endfield-motion.md)。

## 2. 外观规格

### 2.1 画布与底纹

AIC 属于「亮暗并存，按界面功能选」的那类界面：**建造 / 顶视图用暗底**（看线更清楚），**数据简报用浅底**（看数字更清楚）。

| 元素 | 规格 | 等级 |
|---|---|---|
| 画布 | 暗 `#141414`；浅 `#FAFAFA` | 实测（中性阶） |
| 蓝图网格 | 线透明度 **8–12%**，格距 **24 / 32px** 两档（逻辑网格取 8 / 16px，视觉网格是其整数倍） | 实测（官网网格 10–27%，此处取下限）+ 推断 |
| 等高线 | 不透明度 **≤15%**，整体旋转 **−15°** | 实测（云游戏页） |
| 点阵 | 点半径 1px、间距 16px、透明度 8–10% | 实测（官网弹窗 1.5em / 8%） |
| 斜纹 | 6px 方格、−45°、每格两条斜带、带厚 1.9px；**只给未探索区、最高稀有度、条带状表面** | 实测（hatch） |

三条硬约束：

1. **一个视口只选一种底纹**（网格 / 等高线 / 点阵），不要把三种叠在一起；
2. **底纹不压正文**，也不铺满整页；
3. 网格线在 1× 屏上会摩尔纹 —— 不稳定时改用 **6×6 px 的 SVG 平铺**（规范给的做法）。

### 2.2 分区骨架

借家族 **A（运行界面：中心留空、四角停靠）** 与 **E（流程：连线支配版式）**：

```
┌──────────────────────────────────────────────────────┐
│ 顶栏：探索/AIC 切换 · 区域名 · 电力 kW      计划入口 │
├──────┬───────────────────────────────────┬───────────┤
│ 左轨 │                                   │ 详情面板  │
│ 工具 │            工厂画布（中心留空）   │ 设施 /    │
│ 建造 │            节点 + 连线            │ 蓝图 /    │
│ 拆除 │                                   │ 计划      │
├──────┴───────────────────────────────────┴───────────┤
│ 底部：设施列表（选中后放置）   │ 右下：AIC 操作菜单    │
└──────────────────────────────────────────────────────┘
```

| 区域 | 内容 | 依据 |
|---|---|---|
| 顶栏 | 模式切换、区域名、电力读数（等宽） | 一手（Tab 切模式）+ 实测（顶栏胶囊） |
| 左轨 | 建造 / 拆除 / 收纳模式与设施分类 | 社区（操作菜单位置）+ 推断（挪到左轨） |
| 底部 | 设施列表（顶视图内快速建造） | 一手 |
| 右缘 | 详情面板（点设施才出现） | 一手 |
| 右下 | AIC 操作菜单 | 社区 |
| 画布 | **中心留空**，重要读数贴边 | 实测（家族 A 的结构原则） |

> 左轨替代「右下操作菜单」属于**推断**：规范里家族 A 的主菜单是「径向枢纽」，AIC 是全屏工厂，二者都不适合直接套；左轨更接近家族 E 的「侧栏只负责解释与操作」。

### 2.3 节点（设施）

| 项 | 规格 |
|---|---|
| 形状 | 直角矩形；**只有可建造 / 可交互**的节点切角（6–16px，≈高度的 1/4，**切一个角**） |
| 尺寸 | 逻辑 32 / 48 / 64px 三档；图标占节点 60%，四周留白 20% |
| 底座 | 节点下方一块**灰色底座**（家族 E 范式）——让节点「站在」网格上，而不是浮着 |
| 图标 | 白色线稿，不填实；选中时不反色，只加记号 |
| 状态 | 见 §2.4 |

节点状态（**不整体变灰**，规范明确反对）：

| 状态 | 表达 |
|---|---|
| 正常 | 底座 + 线稿图标 |
| 悬停 | 描边加深到 `line-strong`，**不放大、不上浮** |
| 选中 | **角括号**（2px、臂长 12–14px、外扩 4px）或整块白反转 |
| 缺料 / 无电 | 图标边上一个小三角警示 + 端点变暗；节点本身仍可读 |
| 离网 / 断线 | 连线变虚线 + 端点暗；**不断开节点** |
| 在建 | 灰底 + 分段进度 + 短横指示 |
| 完成 | 明暗反转一次 + 黑色圆勾（200ms） |

### 2.4 连线（传送带 / 管道 / 电力）

| 项 | 规格 |
|---|---|
| 走向 | **直角折线**优先（家族 E 的「黄色直角折线」），不用贝塞尔；转角半径 0 |
| 线宽 | 常态 1px `line`；选中 / 通电 3px `signal` |
| 方向 | **只在悬停或选中时**出现箭头 —— 常驻箭头会让满屏都是噪声 |
| 连接成功 | **端点发光**（白 / 黄），而不是只把线染色（官方补丁的核心） |
| 连接失败 | 端点暗 + 断口小记号（两段短粗线错开），不用红色大叉 |
| 交叉 | 交叉处**断开画**（上线跨过时留 2px 缝），或加一个小圆点，二选一，全屏统一 |

### 2.5 资源与读数

| 元素 | 规格 |
|---|---|
| 资源胶囊 | 顶部，圆形图标 + **等宽数字**，与顶栏同一水平线 |
| 产能进度 | 灰轨 + 黄填充；**直角分段块**（每段 8–12px，缝 2px），不用圆头连续条 |
| 电力 | `kW` 读数 + 「用量 / 上限」成对出现（如 `184 / 200 kW`） |
| 告警 | 橙色菱形 + 计数；**每屏最多一处**告警汇总，其余就地标在节点上 |
| 数字语义 | 蓝 = 产出、黄 = 消耗与进度、红 = 超支（家族 F 的固定分工） |

### 2.6 设施详情面板

| 部件 | 规格 | 依据 |
|---|---|---|
| 面板 | `surface-raised` + 1px `line` + **直角**；内边距 16–24px | 实测（卡片页） |
| 标题带 | 高 28–32px，深色底 + 反白字；**左缘 3–4px 黄竖条** | 社区（游戏界面数据列分组头） |
| 属性行 | 名称左对齐、数值右对齐 + 等宽 + 加粗；行间 1px `line` | 实测 |
| 分段 | 「产出 / 消耗 / 存量为上」四行一组，组间 8px | 推断 |
| 操作 | 面板底部一条动作行：主行动**实心黄底墨字**，次行动深色块；**不围整圈描边** | 实测（不围整圈） |
| 关闭 | 右上角 24px 叉，悬停转 90° | 实测 |

### 2.7 浮层

| 浮层 | 进场 |
|---|---|
| 蓝图面板 / 计划面板（右缘） | 从右缘外 8px 淡入，位移 300ms；退场只淡出 200ms |
| 操作菜单（右下） | 从触发侧 4px 淡入，位移 300ms；退场只淡出 200ms |
| 确认框（拆整条产线） | 从下方 8px；遮罩淡入 200ms；**不放大** |

### 2.8 仪表叠层（只给「建造预览 / 蓝图框选 / 顶视图」）

| 元素 | 规格 |
|---|---|
| 取景角 | 16–24px 臂长、**1.5px** 线宽、画面内侧 12px |
| 准星 | 12px，臂长 6px，`accent-ink` |
| 坐标读数 | `font-tech`、**不小于 12px**、`ink-secondary`；内容必须真实（网格坐标 / 缩放 / 阶段 / 延迟） |

三条边界（规范原文）：**每屏只用两三种叠层**；**不进日常操作界面**；**每个读数都必须是真的**——AIC 里最容易犯的就是「随便放几个跳动的数字」。

## 3. 动效规格

### 3.1 时长与缓动

| 用途 | 时长 | 缓动 |
|---|---|---|
| 颜色 / 透明度 | 200ms | `ease-standard` |
| 位移 / 展开 / 形变（默认） | 300ms | `ease-standard` |
| 状态记号（勾、点、角括号、框选角） | **200ms** | `ease-standard` |
| 大面积移动（面板滑入） | 400ms | `ease-emphasis` |
| 入场（通电、整层淡入） | 600ms | `ease-exit` |

**进出不对称**：进 300 / 出 200；**全部不过冲**，不用弹跳与回弹。

### 3.2 链路动效（AIC 的核心）

| 事件 | 怎么动 | 时长 | 之后 |
|---|---|---|---|
| 铺设一条线 | 从起点**擦出**到终点（`clip-path` / `scaleX`，`transform-origin` 在起点） | 300ms | 停在终态 |
| 通电（首次连上） | 高亮**沿路径走一遍**（虚线偏移或分段点亮），走到端点时端点**发白光** | 单程 ≤600ms | **静止**，不留常驻流光 |
| 满载 | 线色 黄 → 橙，端点低频脉动 | 2s 循环 | 仅**一处**（全屏唯一的脉动） |
| 断线 | 实线 → 虚线（200ms），端点暗 | 200ms | 静止 |
| 拆除 | 线从**远离节点的一端**收回 | 300ms | 立即移除 |

> 这条「通电后必须静止」是本规格最重要的决定：终末地的动态只用来**解释因果**（刚发生了什么），
> 而 AIC 是常驻界面——常驻流光会让整张工厂一直在闪。规范的说法是「戏剧性留给入场」。

### 3.3 节点状态动效

| 事件 | 怎么动 | 时长 |
|---|---|---|
| 选中 | 角括号**八段短线**从角顶点伸到满长 | 200ms |
| 取消选中 | 直接消失（记号不反着播） | 0 |
| 建造中 | 分段进度块 + （如需要）不确定进度：块宽 40%、平移 150%、1.2s 一程 | 循环 |
| 建成 | 明暗反转一次，打黑色圆勾 | 200ms |
| 缺料 | 小三角警示淡入；**不闪烁**（闪烁只给"新内容"） | 200ms |

### 3.4 视图操作（铁律：跟手的不加过渡）

| 操作 | 处理 |
|---|---|
| 平移 / 缩放 | **无过渡**，贴着指针与滚轮 |
| 框选 | 填充 8–12% 蓝或白 + 四个取景角；框随指针实时变，**不加过渡** |
| 模式切换（探索 ↔ AIC） | 整层淡入 200ms + 网格随之淡入；**不做滑动、不做缩放** |
| 打开顶视图 | 整层淡入 200ms，随后取景角落位 200ms（八段短线） |
| 焦点跳转（点设施） | 面板从右缘 8px 进；画布**不移动**（移动会让用户丢失方位） |

### 3.5 告警与仪表

- 告警出现：橙色菱形淡入 200ms，计数**滚动数字**只在**首次**滚一次（600ms，先快后慢）；
- 刻度环（若用于产能 / 电力）：**60s 一圈**——慢到几乎不动才是仪表；
- 刻度尺（若放在顶栏下缘）：40s 走一圈、每第五根加粗；**入场闪三下（0.25s）后常亮**；
- 读数变化不做逐帧插值（数字直接换），只有「首次出现」滚一次。

### 3.6 减少动态效果

| 项 | 降级 |
|---|---|
| 所有过渡 | 时长 → 0、延迟 → 0 |
| 通电流光 | 直接到终态（端点已亮） |
| 脉动 / 刻度尺 | 停 |
| 框选 / 平移 | 本来就是瞬时 |
| 必须保证 | **停在终态**（不能停在透明或屏幕外）；状态不只靠动效表达 |

## 4. 实现方案

### 4.1 数据模型（DTO 草案）

```csharp
// 节点：一台设施
sealed class AicNode
{
    public string Id;
    public string Kind;          // 冶炼炉 / 传送带 / 电力节点…
    public double X, Y;          // 逻辑网格坐标（不是像素）
    public int Size;             // 32 / 48 / 64
    public AicNodeState State;   // Normal / Offline / UnderConstruction / Complete / Starved
    public double Progress;      // 0–1，仅在建
}

// 端口：连线端点，决定「发白光」画在哪
sealed class AicPort
{
    public string NodeId;
    public AicPortKind Kind;     // Belt / Pipe / Power
    public double X, Y;
    public bool Connected;
}

// 连线：直角折线，points 是已经算好的拐点
sealed class AicEdge
{
    public string Id;
    public AicPortKind Kind;
    public List<Point> Points;
    public AicEdgeState State;   // Idle / Powered / Overloaded / Broken
    public double Flow;          // 0–1，用于分段点亮与「满载」判定
}
```

三条设计决定：

1. **坐标用逻辑网格**，渲染时才乘缩放 —— 平移 / 缩放不重建数据，只换变换矩阵；
2. **端口是独立对象**：状态反馈要落在端口上（发白光），而不是落在整条线上；
3. **`Points` 预计算**：直角折线在数据变更时算一次，动画与重绘都读它，避免每帧寻路。

### 4.2 渲染分层

| 层 | 内容 | 重绘策略 |
|---|---|---|
| 底纹层 | 网格 / 等高线 / 点阵 | `DrawingBrush` 冻结，**只随缩放换画刷**，不逐帧重绘 |
| 连线层 | 所有 `AicEdge` | `DrawingVisual`，按**脏矩形**重绘；帧内共享冻结的 `Pen`（1px / 3px 两档） |
| 节点层 | 图标 + 底座 + 角括号 | 每节点一个 `DrawingVisual`，选中态只换一层 adornment |
| 叠层 | 取景角、准星、读数 | 单独一层，`IsHitTestVisible = false` |

要点：

- **`Pen` / `Brush` 必须 `Freeze()`**（项目里 `ChartDraw` 已经这么做）——否则每帧新建导致托管分配与 GC 抖动；
- 命中测试**不要每帧遍历所有节点**：按网格桶索引（每桶 = 视觉网格的一格）；
- 线宽只允许 **1px / 3px** 两档，避免为中间值生成新 `Pen` 破坏缓存。

### 4.3 交互状态机

```
Explore ──Tab──► AicIdle ──选设施──► Placing ──放下──► AicIdle
                    │                   │
                    ├──长按拖动──► Dismantling ──松开──► AicIdle
                    └──打开蓝图──► Blueprinting ──保存/取消──► AicIdle
```

原则（来自 AIC 的实证）：**编辑动作是「模式」，不是「每条目上的按钮」**。
所以任何「批量」能力都必须先进入模式，再框选，再执行，再退出——不要在节点上散落复选框。

### 4.4 动效实现

| 动效 | WPF 手段 | 注意 |
|---|---|---|
| 淡入 / 位移 | `DoubleAnimation` 于 `Opacity` / `TranslateTransform` | 合成器动画，无每帧托管分配 |
| 角括号 / 取景角落位 | 对 8 段短线的长度或 `ScaleTransform` 做 200ms 动画 | 与规范 `animate-bracket-in` 同构 |
| 连线擦出 | `ScaleTransform`（`RenderTransformOrigin` 在起点）或 `Clip` | `Clip` 会裁掉线宽的一半，建议用 `ScaleTransform` |
| 通电流光 | `DashStyle` + `DashOffset` 逐帧推进 | **只在通电那一次**跑，≤600ms；结束即停表 |
| 分段进度 | 每段独立 `Rectangle`，改 `Width` 或整段可见性 | 不要用一条渐变去「假装」分段 |
| 脉动 | `DoubleAnimation` `AutoReverse` + `RepeatBehavior` | 全屏只允许一处；`ReduceMotion` 优先 |

**帧调度**：项目已有 15ms 帧计时（`OverlayWindow` / `RenderScheduler`）。AIC 若做成卡片，应复用同一套调度，
不要自起 `DispatcherTimer`；逐帧部分（流光、等高线）做成「有动画时才订阅帧事件」。

### 4.5 性能预算

| 项 | 预算 |
|---|---|
| 目标帧率 | 60fps（与卡片动效一致） |
| 连线层单帧重绘 | ≤4ms（脏矩形范围内） |
| 单帧托管分配 | 0（Pen/Brush 冻结、点列表复用） |
| 节点数 | ≤200 走矢量渲染；>200 时降级：关流光、底纹改图片平铺、节点图标缓存为 `RenderTargetBitmap` |
| 与毛玻璃 | **不共存**：模糊重绘 + 逐帧连线会互相拖垮，开毛玻璃时该卡自动关闭动效 |
| 内存 | 图标位图按 1×/1.5×/2× 三档缓存，不做逐缩放重建 |

### 4.6 与 MirrorpondHUD 的接入

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 新增内置卡插件 `builtin.aic`，走 `CardPluginLoader`，manifest `apiVersion = 2` | 与现有六张卡同一条路径；不动宿主 |
| B | 在 `UiKit` 加 `AicCanvas` 控件，再挂一张卡 | 控件可复用，但 `UiKit` 变更会重建全部插件 |
| C | 塞进现有「硬件指标」卡 | 不可取：两种信息架构混在一起，两边都不成立 |

选 A 的原因：AIC 是**一张独立的工作区卡**（有模式、有画布、有详情面板），符合「一个插件一张卡」的既有划分；
且插件无热重载，独立 DLL 出问题不会带崩宿主显示。

## 5. 待实机校正清单

拿到实机截图后，**必须逐条复核**，并把本文对应条目的等级从 `推断` / `社区` 升为 `实测`：

| # | 待校正项 | 为什么重要 |
|---|---|---|
| 1 | 网格格距与透明度（本文取 24/32px、8–12%） | 决定整张画布的密度感 |
| 2 | 游戏内信号黄的实际取值（本文用 `#FFFA00`，暖档 `#FCEA00`） | 决定「像不像」 |
| 3 | 连线的拐角与交叉画法 | 工厂图的辨识度主要在这里 |
| 4 | 节点尺寸与图标占比（本文 32/48/64、60%） | 决定一屏能放多少设施 |
| 5 | 进度条是否分段、分段粒度 | 本文假设分段，未证实 |
| 6 | 详情面板的标题带高度与是否反白 | 本文借了社区归纳 |
| 7 | 通电反馈是「端点发光」还是「整线染色」 | 官方只说了「改进视觉反馈」 |
| 8 | 游戏内字体与数字是否等宽 | 本文按品牌层推定 |

## 6. 验收清单

1. 一眼能看出**当前模式**（探索 / AIC / 建造 / 拆除 / 蓝图），且模式切换有整层反馈；
2. **连接正确时端点可见地亮**，不是只有一条变色的线；
3. 画布中心留空，读数贴边，不挡工厂；
4. 底纹只有一种，且**不压正文**；
5. 状态不靠整体变灰表达（锁定 / 缺料 / 断线各有记号）；
6. 告警每屏最多一处汇总 + 就地标注；
7. 通电流光**只播一次**，之后静止；全屏脉动最多一处；
8. 框选 / 平移 / 缩放**无过渡**；
9. 开「减少动态效果」后：全部瞬时、停在终态、流光与刻度尺停；
10. 节点 200 个时仍能 60fps，且单帧 0 托管分配。
